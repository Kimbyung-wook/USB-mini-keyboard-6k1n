# 설정 통신 프로토콜 v2

PC 설정 프로그램(GUI)과 키보드 펌웨어가 공유하는 규격입니다. 펌웨어와 GUI는 모두 이 문서를 기준으로 구현합니다.

| 버전 | 펌웨어 | 변경 |
|---|---|---|
| v1 | 1.0 | 최초 |
| v2 | 1.1 | [패턴 암호](#패턴-암호) 추가: HELLO 바이트 9(잠금 상태), status `LOCKED`, 블롭의 10번째 슬롯. HELLO 바이트 10~16(patch 버전, 빌드 날짜). 나머지는 v1과 같음. GUI 1.1은 v1 장치도 그대로 지원(잠금 기능만 꺼짐) |
| v2 | 1.4 | 프로토콜 버전은 그대로. [설정 슬롯](#설정-슬롯)(자동 잠금 시간) 추가, HELLO 바이트 22 bit3로 지원 여부를 알림. 1.3 이하 펌웨어는 설정 슬롯을 무시함 |

## USB 구성

| 항목 | 값 |
|---|---|
| VID / PID | `0x1209` / `0xC55D` (개발용, 추후 변경 가능) |
| 인터페이스 0 | HID 키보드 (Boot keyboard, 문자열 출력) |
| 인터페이스 1 | **Vendor HID**: Usage Page `0xFF00`, Usage `0x01`, 설정 통신 |
| 리포트 | Report ID 없음, IN/OUT 각 **64바이트** 고정 |

- GUI는 `hidapi`로 VID/PID가 일치하고 `usage_page == 0xFF00`인 인터페이스를 엽니다(Windows에서는 인터페이스마다 장치 경로가 따로 나옴).
- 부트로더 모드의 장치는 VID/PID `0x4348` / `0x55E0`입니다(WCH ROM 부트로더, HID 아님).

## 패킷 형식

모든 패킷은 64바이트이고, 남는 부분은 0으로 채웁니다. 다중 바이트 정수는 **리틀 엔디언**입니다.

**요청 (PC → 장치, OUT 리포트)**

| 바이트 | 내용 |
|---|---|
| 0 | `cmd` |
| 1 | `seq`: 요청 번호(0~255 순환). 응답에 그대로 돌려줌 |
| 2~63 | 명령별 인수 |

**응답 (장치 → PC, IN 리포트)**

| 바이트 | 내용 |
|---|---|
| 0 | `cmd | 0x80` |
| 1 | `seq` (요청과 같은 값) |
| 2 | `status` |
| 3~63 | 명령별 결과 |

GUI는 요청 하나를 보내고 응답을 받은 뒤 다음 요청을 보냅니다(동시에 여러 요청 없음). 응답 대기 제한 시간은 1000ms입니다. `COMMIT`은 Flash 쓰기 때문에 2000ms까지 기다립니다.

**status 값**

| 값 | 이름 | 의미 |
|---|---|---|
| 0 | `OK` | 성공 |
| 1 | `BAD_CMD` | 알 수 없는 명령 |
| 2 | `BAD_ARG` | 인수 범위 오류 (오프셋/길이/슬롯 번호) |
| 3 | `BAD_CRC` | COMMIT 시 CRC 불일치 |
| 4 | `TOO_BIG` | 저장 용량 초과 |
| 5 | `FLASH_ERR` | Flash 지우기/쓰기 실패 |
| 6 | `BUSY` | 문자열 출력 중이라 처리 불가 |
| 7 | `LOCKED` | 잠금 상태라 처리 불가 (v2, READ/TEST/BOOT) |

## 명령

### `0x01` HELLO

장치 정보를 확인합니다. 연결 직후 가장 먼저 보냅니다.

- 요청 인수: 없음
- 응답 결과:

| 바이트 | 내용 |
|---|---|
| 3 | 프로토콜 버전 (`2`, 펌웨어 1.0은 `1`) |
| 4 | 펌웨어 major |
| 5 | 펌웨어 minor |
| 6 | 슬롯 수 (`9`) |
| 7~8 | 설정 블롭 최대 크기(바이트, uint16). DataFlash에 저장하므로 `128` |
| 9 | 잠금 상태 (v2): bit0 패턴 암호 있음, bit1 지금 잠김, bit2 5번 틀려서 막힘. v1에서는 무시 |
| 10 | 펌웨어 patch (v2). 버전 표기는 `major.minor.patch` |
| 11~12 | 빌드 연도 (v2, uint16). `0`이면 빌드 날짜 없음(`tools/build_fw.ps1`이 아닌 방법으로 빌드) |
| 13~16 | 빌드 월, 일, 시, 분 (v2, 각 1바이트, PC의 현지 시각) |
| 17 | 보드 정보 버전: `0` = 없음(펌웨어 1.2.x까지), `1` = 아래 18~35 있음. 없으면 GUI는 키 6 + 노브 1, 2행, CH552로 봅니다 |
| 18 | 칩 ID (부트로더 Detect와 같은 번호, CH552 = `0x52`) |
| 19 / 20 / 21 | 키 수 K / 노브 수 N / 키 배치 행 수 |
| 22 | 기능 비트: bit0 RGB LED, bit1 패턴 암호, bit2 무선(예약), bit3 [설정 슬롯](#설정-슬롯)(자동 잠금, 펌웨어 1.4) |
| 23 | 예약 (`0`) |
| 24~31 | 보드 이름 (ASCII 8바이트, 남는 곳은 `0`) |
| 32~35 | 칩 고유 ID (4바이트, 모르면 `0`) |

슬롯 수(바이트 6)는 `K + 3N`이어야 합니다. 자세한 규칙은 [docs/BOARD_INFO.md](BOARD_INFO.md)를 보세요.

### `0x02` READ

설정 블롭의 일부를 읽습니다.

- 요청 인수: 바이트 2~3 `offset`(uint16), 바이트 4 `len`(1~56)
- 응답 결과: 바이트 3~4 `offset`, 바이트 5 `len`(실제로 읽은 길이), 바이트 6~ 데이터
- `offset + len`이 최대 크기를 넘으면 `BAD_ARG`
- 잠겨 있으면 `LOCKED`

### `0x03` WRITE

설정 블롭의 일부를 장치의 임시 영역에 씁니다. `COMMIT` 전까지는 저장된 설정과 출력 동작에 영향이 없습니다.

- 요청 인수: 바이트 2~3 `offset`, 바이트 4 `len`(1~56), 바이트 5~ 데이터
- 응답 결과: 없음
- 블롭은 `offset = 0`부터 순서대로 빈틈없이 씁니다. 장치는 순서가 어긋나면 `BAD_ARG`를 돌려줄 수 있습니다.

### `0x04` COMMIT

임시 영역에 쓴 블롭을 검증하고 확정합니다.

- 요청 인수: 바이트 2~3 `total_len`(헤더 포함 전체 길이), 바이트 4~5 `crc16`(블롭 헤더의 CRC와 같은 값)
- 장치는 헤더의 매직/버전/길이와 CRC, 패턴 암호 형식을 검사하고, 맞으면 저장 영역에 확정합니다. 블롭 뒤의 남는 영역은 `0xFF`로 지웁니다(이전 설정이 READ로 남아 보이지 않도록).
- WRITE/COMMIT은 **잠겨 있어도 됩니다**. 새 설정이 기존 설정 전체를 지우고 대신하므로 기존 내용이 드러나지 않고, 패턴을 잊었을 때 다시 시작하는 방법이 됩니다. 잠긴 상태에서 저장하면 새 설정의 패턴 암호 유무로 잠금 상태가 다시 정해집니다. 풀린 상태에서 저장하면 다음에 꽂을 때까지 풀린 상태가 유지됩니다.
- 응답 결과: 없음 (`OK`, `BAD_ARG`, `BAD_CRC`, `TOO_BIG`, `FLASH_ERR`)

### `0x05` TEST

해당 슬롯의 문자열을 실제로 타이핑합니다(저장된 설정 기준).

- 요청 인수: 바이트 2 `slot`(0~8)
- 응답은 출력을 **시작할 때** 바로 돌려줍니다. 출력 중에 받은 다른 명령에는 `BUSY`로 응답할 수 있습니다.
- 잠겨 있으면 `LOCKED`

### `0x06` BOOT

부트로더로 재시작합니다(펌웨어 업데이트용).

- 요청 인수: 없음
- 장치는 `OK` 응답을 보낸 뒤 USB 연결을 끊고 부트로더로 점프합니다. 이후 `4348:55E0` 장치가 나타납니다.
- 잠겨 있으면 `LOCKED`

## 설정 블롭 형식 (v1)

장치에 저장되는 설정 전체를 하나의 바이트열(블롭)로 다룹니다. GUI는 블롭 전체를 읽고, 편집한 뒤, 전체를 다시 씁니다.

```
오프셋  크기  내용
0       2     매직 "MK" (0x4D, 0x4B)
2       1     블롭 버전 (1)
3       1     슬롯 수 N (9, 패턴 암호가 있으면 10, 설정 슬롯까지 있으면 11)
4       2     페이로드 길이 L (uint16, 헤더 8바이트 제외)
6       2     CRC16 (페이로드 L바이트에 대해 계산)
8       L     페이로드: 슬롯 N개가 순서대로
```

**슬롯 하나의 형식**: `len`(uint16) + `len`바이트의 매크로 문자열(ASCII)

- 매크로 문자열은 아래 "매크로 문법"의 **원문 텍스트를 그대로** 저장합니다. 해석은 장치가 출력할 때 합니다.
- 빈 슬롯은 `len = 0`입니다.
- 전체 길이 `8 + L`은 HELLO의 최대 크기를 넘을 수 없습니다.
- 10번째 슬롯(슬롯 9)은 문자열이 아니라 **패턴 암호**입니다. 아래 [패턴 암호](#패턴-암호)를 보세요. 패턴 암호가 없으면 슬롯 수 9로 저장해서 펌웨어 1.0과 같은 블롭이 됩니다.
- 11번째 슬롯(슬롯 10)은 **설정 슬롯**입니다. 아래 [설정 슬롯](#설정-슬롯)을 보세요.
- 펌웨어는 자기가 아는 슬롯보다 뒤에 있는 슬롯을 검사하지 않고 무시합니다(형식만 맞으면 됨). 그래서 새 GUI가 슬롯을 더 붙인 블롭도 예전 펌웨어가 받아들입니다.

**CRC16**: CRC-16/CCITT-FALSE (다항식 `0x1021`, 초깃값 `0xFFFF`, 반사 없음, 최종 XOR 없음). 검증값: ASCII `"123456789"` → `0x29B1`.

**블롭이 유효하지 않을 때**(새 장치, 손상): READ는 그대로 바이트를 돌려주고, GUI는 매직/CRC 검사에 실패하면 "설정 없음"으로 보고 빈 슬롯 9개로 시작합니다. 장치도 유효하지 않은 블롭이면 모든 슬롯을 빈 것으로 취급합니다.

## 슬롯 번호

| 슬롯 | 입력 |
|---|---|
| 0~2 | 키 A, B, C (윗줄, 왼쪽부터) |
| 3~5 | 키 D, E, F (아랫줄, 왼쪽부터) |
| 6 | 노브 시계 방향 한 칸 |
| 7 | 노브 반시계 방향 한 칸 |
| 8 | 노브 누르기 |
| 9 | 패턴 암호 (타이핑하지 않음, TEST 불가) |

## 설정 슬롯

패턴 암호 슬롯 다음 슬롯(6키 키보드는 슬롯 10)입니다. 펌웨어 1.4부터 쓰고, HELLO 바이트 22의 bit3가 1이면 지원합니다.

| 바이트 | 내용 |
|---|---|
| 0 | 자동 잠금 시간(분, 0~255). `0` = 자동 잠금 안 함 |
| 1~ | 예약. 펌웨어는 읽지 않으므로, 나중에 설정이 늘어도 길이만 늘리면 됩니다 |

- GUI는 **패턴 암호가 있고 자동 잠금 시간이 0이 아닐 때만** 이 슬롯을 씁니다(3바이트: 길이 2 + 1). 그 밖에는 슬롯 수 9나 10의 예전 블롭과 똑같습니다.
- 설정 슬롯이 없거나 길이가 0이면 자동 잠금 시간 0으로 봅니다.

## 패턴 암호

패턴 암호가 저장되어 있으면 키보드는 **꽂을 때마다 잠긴 상태로 시작**합니다(펌웨어 1.1, 프로토콜 v2).

- **저장 형식**: 블롭의 슬롯 9. 길이 0(잠금 없음) 또는 4~8바이트이고, 각 바이트는 입력 하나의 슬롯 번호(0~8)입니다. 예: `A → B → C → 노브 시계 방향` = `00 01 02 06`. 다른 길이나 9 이상의 값이 있으면 COMMIT이 `BAD_ARG`로 거부합니다. 패턴 하나가 `2 + 단계 수`바이트를 씁니다.
- **잠긴 동안**: 키와 노브 입력은 무시합니다. READ/TEST/BOOT는 `LOCKED`로 거부됩니다. HELLO, WRITE, COMMIT은 됩니다.
- **패턴 입력 시작**: 노브를 2초 누르고 있으면 패턴 입력이 시작됩니다(펌웨어 1.2부터. 1.3.0까지는 3초, 1.3.1부터 2초). 패턴 입력 중의 키/노브 입력은 타이핑되지 않습니다.
- **입력 판정**: 입력이 패턴 길이만큼 모이면 한꺼번에 비교합니다. 맞으면 풀리고, 틀리면 잠긴 상태로 돌아갑니다(다시 노브 2초부터). 10초 동안 입력이 없으면 패턴 입력을 취소합니다(풀기와 다시 잠그기 모두. 틀린 횟수에 넣지 않음).
- **다시 잠그기**: 풀린 상태에서 노브를 2초 누르고 같은 패턴을 입력하면 다시 잠깁니다. 틀리거나 시간이 지나면 풀린 상태 그대로이고, 5번 틀리면 잠깁니다(차단이 아닌 잠김. 횟수는 다시 잠그기에 성공하거나 잠김에서 풀리면 0으로). 이 동안에는 HELLO도 풀린 상태로 보고합니다.
- **노브 누르기 슬롯**: 패턴 암호가 저장되어 있으면 노브 누르기는 뗄 때(2초 미만) 입력됩니다.
- **5번 틀리면** 패턴 입력도 받지 않습니다. 키보드를 다시 꽂아야 합니다.
- **LED**: 잠김 = 꺼짐 + 3초마다 빨강 짧게 깜빡, 패턴 입력 중 = 빨강 계속, 풀기 5번 틀려 막힘 = 빨강 계속 깜빡임, 풀림 = 파랑(키를 누르면 초록 잠깐). 상태도는 README.md "잠금 상태도".
- **자동 잠금** (펌웨어 1.4): 설정 슬롯의 자동 잠금 시간이 N분(1~255)이면, 풀린 상태에서 **N분 동안 입력이 없을 때** 잠깁니다. 해제 실패 횟수는 새로 5번입니다. "입력"은 키/노브 입력(패턴 입력 포함)과 GUI의 HELLO가 아닌 명령(READ, WRITE, COMMIT, TEST, BOOT)입니다. GUI는 연결되어 있는 동안 2초마다 HELLO를 보내므로 HELLO는 입력으로 치지 않습니다(GUI만 켜 두면 잠기지 않는 일이 없도록). 시간은 패턴 입력 중이거나 잠겨 있는 동안에는 세지 않고, 풀린 상태가 될 때부터 다시 셉니다.
- **다시 잠기는 때**: USB를 다시 꽂을 때(전원이 다시 들어올 때), 위의 다시 잠그기, 또는 자동 잠금.
- **보안 수준**: 주변 사람이 키를 눌러 저장된 문자열을 쓰거나 GUI로 읽어 가는 것을 막는 정도입니다. 장치를 가져가 펌웨어를 새로 굽는 공격(부트로더는 키 D를 누른 채 꽂으면 들어갈 수 있음)이나 DataFlash를 직접 읽는 공격은 막지 못합니다. 비밀번호 같은 민감한 문자열은 저장하지 않는 것이 좋습니다.

## 매크로 문법

일반 문자는 그대로 입력되고, `{...}` 안은 특수 동작입니다.

| 표기 | 동작 |
|---|---|
| 인쇄 가능한 ASCII (`0x20`~`0x7E`, `{` `}` 제외) | 해당 문자 입력 |
| `{{` / `}}` | 문자 `{` / `}` 입력 |
| `{ENTER}` `{TAB}` `{ESC}` `{BS}` `{DEL}` `{SPACE}` | 해당 키 |
| `{UP}` `{DOWN}` `{LEFT}` `{RIGHT}` `{HOME}` `{END}` `{PGUP}` `{PGDN}` `{INS}` | 해당 키 |
| `{F1}` ~ `{F12}` | 기능 키 |
| `{DELAY:n}` | n밀리초 대기 (1~10000) |
| `{CTRL+x}` `{SHIFT+x}` `{ALT+x}` `{WIN+x}` | 조합키. 수식키는 `+`로 여러 개 연결 가능(예: `{CTRL+SHIFT+ESC}`). `x`는 문자 하나 또는 위 키 이름(예: `{ALT+F4}`, `{WIN+R}`) |

- 키 이름과 수식키는 대소문자를 구분하지 않습니다.
- 줄바꿈 문자(`\n`)는 `{ENTER}`와 같게 처리합니다. 그 외 제어 문자와 비 ASCII 문자(한글 등)는 허용하지 않습니다. GUI가 저장 전에 거부합니다.
- 키 입력은 미국(US) 키보드 배열 기준입니다.
