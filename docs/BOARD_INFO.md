# 보드 정보와 GUI 자동 구성 설계안

> 상태 (2026-10-31): 진행 순서 **1~4번 완료**, 두 번째 보드 **MK6K1NL**(키마다 LED, 펌웨어·GUI 1.5.0) 추가, GUI 1.6.0에서 업데이트 창에 **장입할 보드** 선택(처음 설치 포함). 보드별 핀은 [PINMAP.md](PINMAP.md).
>
> 이전 상태 (2026-10-26): "정할 것" 5가지는 모두 **권장안**으로 정했습니다. 진행 순서 **1~3번 완료**: 펌웨어 1.3.0이 HELLO 바이트 17~35로 보드 정보를 보내고 hex에 식별 문자열을 넣으며, GUI는 그 배치로 화면을 만들고, 펌웨어 업데이트 창은 칩 표(`gui/chips.py`)와 보드 목록(`gui/boards.py`)으로 칩·업로더 옵션·진입 방법을 고르고 hex의 식별 문자열을 확인합니다.

## 목표

- 키보드가 자기 자신을 GUI에 알려 줍니다: **칩, 키 수, 노브 수, 키 배치, 저장 용량, 보드 이름**.
- GUI는 이 정보를 보고 **화면(키 그림, 편집 칸, 패턴 암호 버튼)을 만듭니다**. 지금처럼 "키 6개 + 노브 1개"를 코드에 박아 두지 않습니다.
- 펌웨어 업데이트 창은 칩에 맞는 **최대 크기와 업로드 도구**를 고르고, 고른 펌웨어 파일이 **이 보드용인지** 확인합니다.
- 지금 키보드(6키 + 노브 1개, CH552)와 이미 배포된 펌웨어(1.0~1.2.1)는 그대로 동작해야 합니다.

칩 이름보다 **키/노브 수를 키보드가 직접 알려 주는 것**이 핵심입니다. 같은 CH552라도 6키, 8핀, 9핀 키보드는 배치가 다르고, 반대로 칩이 달라도 배치가 같을 수 있기 때문입니다.

## 1. 슬롯 번호 규칙 (일반화)

지금 규칙(키 0~5, 노브 6~8, 패턴 암호 9)을 그대로 늘린 형태입니다. 6키 + 노브 1개에서는 지금과 **완전히 같은 번호**가 됩니다.

| 슬롯 | 입력 |
|---|---|
| `0` ~ `K-1` | 키 K개 (배치 순서: 윗줄 왼쪽부터, 행 우선) |
| `K + 3n + 0` | 노브 n 시계 방향 |
| `K + 3n + 1` | 노브 n 반시계 방향 |
| `K + 3n + 2` | 노브 n 누르기 |
| `S` (= `K + 3N`) | 패턴 암호 (블롭에만 있음, 타이핑하지 않음) |

- 슬롯 수 `S = K + 3N`. HELLO 바이트 6(지금도 있는 "슬롯 수")이 이 값입니다.
- 블롭 형식은 바뀌지 않습니다. 블롭의 슬롯 수는 `S`(패턴 없음) 또는 `S + 1`(패턴 있음).
- 패턴 암호의 각 단계는 `0` ~ `S-1` 사이의 슬롯 번호입니다(지금은 0~8).
- 한계: `S ≤ 63`으로 둡니다. 블롭 형식으로는 255까지 되지만, 슬롯마다 2바이트 길이 정보가 붙어 작은 DataFlash(128바이트)에서는 슬롯이 많을수록 문자열 자리가 줄고, GUI 화면도 감당할 수 있는 정도로 제한합니다. 예: 키 15개 + 노브 3개 = 24.

## 2. HELLO 확장

HELLO 응답(64바이트)의 바이트 17부터 보드 정보를 붙입니다. 펌웨어 1.3부터 채웁니다.

| 바이트 | 내용 | 6키 키보드 값 |
|---|---|---|
| 17 | 보드 정보 버전 (`0` = 없음, `1` = 이 표) | `1` |
| 18 | 칩 ID: 부트로더 Detect가 돌려주는 값과 같은 번호 | `0x52` (CH552) |
| 19 | 키 수 K | `6` |
| 20 | 노브 수 N | `1` |
| 21 | 키 배치 행 수 R (열 수는 `ceil(K / R)`, 마지막 줄은 덜 찰 수 있음) | `2` |
| 22 | 기능 비트: bit0 RGB LED 있음, bit1 패턴 암호 지원, bit2 무선(예약) | `0x03` |
| 23 | 예약 (`0`) | `0` |
| 24~31 | 보드 이름 (ASCII 8바이트, 남는 곳은 `0`) | `"MK6K1N"` |
| 32~35 | 칩 고유 ID (4바이트, 모르면 `0`) — 아래 "정할 것" 3번 | `7D E2 0F BD` |

- 바이트 7~8의 **저장 용량**(지금도 있음)은 그대로 씁니다. 칩마다 DataFlash가 다르면 펌웨어가 그 값을 보냅니다.
- 바이트 17이 `0`이면(펌웨어 1.0~1.2.x, 그 자리가 0으로 채워져 있음) GUI는 **기본 보드**로 봅니다: CH552, 키 6개, 노브 1개, 2행, 이름 `MK6K1N`.
- 펌웨어 쪽 비용: 상수 19바이트를 `__code` 표에서 복사하는 반복문 정도라 약 40~60바이트로 예상합니다.

### 프로토콜 버전을 올릴지

| 방법 | 장점 | 단점 |
|---|---|---|
| **A. v2 그대로, 바이트 17로 구분 (권장)** | 예전 GUI(1.2)도 새 펌웨어의 6키 키보드와 그대로 동작. 예전 GUI는 슬롯 수가 9가 아닌 보드를 "슬롯 수가 맞지 않습니다"로 거부하므로 잘못 쓰지도 않음 | 버전 번호만 보고는 보드 정보 유무를 모름(바이트 17을 봐야 함) |
| B. v3로 올림 | 규칙이 깔끔함 | 예전 GUI가 6키 키보드까지 "지원하지 않는 버전"으로 거부함 |

## 3. GUI 구조

### 3-1. `Board` (새 개념, `gui/protocol.py`)

```python
@dataclass(frozen=True)
class Board:
    chip_id: int          # 0x52
    keys: int             # K
    knobs: int            # N
    rows: int             # R
    name: str             # "MK6K1N"
    capacity: int         # HELLO 바이트 7~8
    uid: bytes = b""

    slot_count  -> K + 3N
    lock_slot   -> slot_count
    slot_names()        # ["A".."F", "1↻", "1↺", "1●", ...]  (노브가 하나면 지금처럼 "CW/CCW/PRESS")
    slot_labels_ko()    # ["키 A", ..., "노브 시계 방향", ...] (노브가 여럿이면 "노브 2 시계 방향")
    lock_step_names()   # 패턴 암호 버튼 글자
    chip -> ChipInfo    # 아래 칩 표에서 찾음
```

- 키 이름: 26개까지 `A`~`Z`, 그 이상은 `K27`처럼 번호. 지금 키보드는 A~F 그대로입니다.
- `DEFAULT_BOARD`: 위의 기본 보드. 바이트 17이 `0`이면 이것을 씁니다.

### 3-2. 고정값을 없앨 곳

| 파일 | 지금 | 바꿀 것 |
|---|---|---|
| `protocol.py` | `SLOT_COUNT = 9`, `SLOT_LOCK = 9`, `SLOT_NAMES`, `SLOT_LABELS_KO`, `LOCK_STEP_NAMES`, `SLOT_KNOB_*` | `Board`의 속성으로. `encode_blob`/`decode_blob`/`blob_size`/`lock_error`가 `slot_count`를 인자로 받음 |
| `protocol.py` `HelloInfo` | 바이트 0~16만 해석 | 바이트 17~35 해석, `board` 속성 |
| `device.py:117` | 슬롯 수가 9가 아니면 연결 거부 | `slot_count == K + 3N`인지만 확인(보드 정보와 슬롯 수가 어긋나면 거부) |
| `widgets.py` `DeviceView` | 키 6개 2×3 + 노브 1개 고정 | `Board`로 만듦: 키 R행 격자 + 노브 N개를 오른쪽에 세로로. 연결할 때마다 다시 만듦 |
| `widgets.py` `LockPatternEditor` | 버튼 9개 고정 | `slot_count`개 버튼(키 격자 + 노브별 3개) |
| `app.py` | `[""] * p.SLOT_COUNT` 여러 곳 | `self.board.slot_count`. 연결이 끊기면 지금처럼 화면을 비우고, 연결되면 그 보드로 화면을 다시 만듦 |
| `backup.py` (JSON) | 슬롯 9개 고정 | 파일에 `board`(이름, 키/노브 수) 기록. 불러올 때 보드가 다르면 묻기: 같은 이름의 슬롯(예: "키 A")끼리만 옮길지, 취소할지 |
| `transport.py` `MockDevice` | 6키 고정 | `board` 인자로 아무 배치나 흉내(테스트용) |

### 3-3. 화면 배치 규칙

- 키: `R`행, 열 수 `ceil(K / R)`. 버튼 최소 크기는 키 수에 따라 줄임(예: 12개 이상이면 72×56).
- 노브: 키 격자 오른쪽에 노브마다 원 하나 + 동작 버튼 3개. 노브가 0개면 노브 영역을 숨김.
- 창 제목/연결 막대: `● 연결됨 · MK6K1N (CH552, 키 6 + 노브 1) · 펌웨어 v1.3.0 (빌드 …) · 용량 128바이트`.
- 키 수가 많아도 편집 칸(오른쪽 매크로 편집기)은 하나이므로 화면 크기는 크게 늘지 않습니다.

## 4. 칩 표와 펌웨어 업데이트

`gui/chips.py`(새 파일) 한 곳에 칩별 값을 모읍니다. 업데이트 창의 `CH552`, `14336` 고정값을 이 표로 바꿉니다.

| 칩 ID | 이름 | 펌웨어 최대 크기 | 업로드 도구 | 상태 |
|---|---|---:|---|---|
| `0x51` | CH551 | 10,240 | vnproch55x `-t CH551` | 펌웨어 미지원(USB 버퍼 축소 필요) |
| `0x52` | CH552 | 14,336 | vnproch55x `-t CH552` | 지원 |
| `0x54` | CH554 | 14,336 | vnproch55x `-t CH554` (확인 필요) | 미확인 |
| CH57x 계열 | CH571/573 등 | 칩별 | 다른 도구(예: wchisp) | 펌웨어 이식 필요 |

- **업데이트 모드 칩 목록**: 부트로더 Detect가 돌려준 칩 ID로 이 표를 찾아 최대 크기와 업로드 도구를 정합니다. 표에 없거나 "미지원"이면 [장입]을 막고 이유를 보여 줍니다.
- **펌웨어 파일 확인**: 펌웨어 안에 식별 문자열을 하나 넣습니다(예: `"MKFW1:MK6K1N:CH552"`, 약 20바이트). GUI는 hex를 읽어 이 문자열을 찾고,
  - 칩이 업데이트 모드의 칩과 다르면 → 장입 막음
  - 보드 이름이 연결되어 있던 키보드와 다르면 → "다른 키보드용 펌웨어입니다" 경고 후 사용자가 확인해야 장입
  - 문자열이 없으면(예전 펌웨어, 다른 사람의 펌웨어) → "확인할 수 없는 펌웨어" 경고
- 연결된 키보드의 칩 고유 ID(HELLO 32~35)와 업데이트 모드 칩 목록의 ID가 같으면 "방금 연결되어 있던 키보드"라고 표시합니다. 여러 대를 꽂아 두었을 때 헷갈리지 않게 합니다.

## 5. 보드 구분

칩은 두 계열(CH55x, CH57x)이지만, **같은 칩에 키 수가 다른 키보드**도 있고 같은 키 수라도 기판이 다를 수 있습니다. 그래서 칩이나 키 수가 아니라 **보드(제품·기판)** 를 기준으로 구분합니다.

- 보드마다 이름 하나와 펌웨어 빌드 하나가 있습니다. 칩, 키/노브 수, 핀 배치, 부트로더 진입 핀은 보드에 딸린 값입니다.
- 키 수를 실행 중에 알아내지는 않습니다. 연결되지 않은 핀은 "안 눌린 키"와 똑같이 읽혀서 구분할 수 없습니다.
- 보드 이름(HELLO 24~31, 8자)은 `MK` + 키 수 + `K` + 노브 수 + `N`(예: `MK6K1N`, `MK9K0N`)을 기본으로 하고, 키 수가 같은데 기판이 다르면 끝에 구분 글자를 붙입니다(예: `MK9K0NB`).

### 5-1. 보드 목록 (`gui/boards.py`, 새 파일)

GUI가 아는 보드를 한 곳에 모읍니다. 펌웨어의 보드 파일(`src/boards/*.h`)과 이름이 1:1로 맞습니다.

| 항목 | 예 (지금 키보드) | 쓰는 곳 |
|---|---|---|
| 보드 이름 | `MK6K1N` | HELLO, 펌웨어 식별 문자열, 처음 설치 때 목록 |
| 설명 | "6키 + 노브 1개 (CH552G)" | 처음 설치 때 목록 |
| 칩 계열 / 칩 ID | CH55x / `0x52` | 업데이트 모드 칩과 맞춰 보기, 업로드 도구 고르기 |
| 키 수 / 노브 수 / 행 수 | 6 / 1 / 2 | 펌웨어 없이도 화면을 그릴 때(처음 설치 미리 보기) |
| **부트로더 진입 핀** | P1.5 (키 D) | 업로드할 때 함께 쓰는 진입 설정(아래 5-3) |
| 사용자 안내 | "키 D를 누른 채 꽂으세요" | 업데이트 모드 들어가는 방법 안내 |
| 펌웨어 파일 | `macro_keyboard-MK6K1N.hex` | 처음 설치 때 기본으로 고르는 파일 |

- HELLO의 보드 정보가 진짜 값이고, 목록은 **펌웨어가 아직 없을 때**(업데이트 모드, 처음 설치) 쓰는 참고 자료입니다. 둘이 다르면 HELLO를 믿습니다.
지금 목록에 있는 보드:

| 보드 이름 | 설명 | 칩 | 키 / 노브 / 행 | 진입 핀 | 펌웨어 파일 |
|---|---|---|---|---|---|
| `MK6K1N` | 6키 + 노브 1개, LED 1개 | CH552 | 6 / 1 / 2 | P1.5 (키 D) | `macro_keyboard-MK6K1N.hex` |
| `MK6K1NL` | 6키 + 노브 1개, 키마다 LED (핀은 MK6K1N과 같음, 2026-10-31) | CH552 | 6 / 1 / 2 | P1.5 (키 D) | `macro_keyboard-MK6K1NL.hex` |

- MK6K1NL은 이름 규칙(위 6절)대로 키 수가 같고 기판이 다른 보드라 끝에 구분 글자 `L`(키마다 LED)을 붙였습니다. 공장 펌웨어(`1189:8890`)에서는 키로 업데이트 모드에 들어가지 않아, 처음에는 D+ 풀업으로 올립니다([test_mk6k1nl](../firmware/test_mk6k1nl/README.md)).
- 목록에 없는 보드도 HELLO에 보드 정보가 있으면 화면은 그대로 만들어집니다(업데이트 창만 "알 수 없는 보드"로 조심스럽게 동작).

### 5-2. GUI가 보드를 알아내는 세 가지 상황

| 상황 | GUI가 알 수 있는 것 | 보드를 정하는 방법 |
|---|---|---|
| ① 우리 펌웨어가 돌고 있을 때 | HELLO로 보드 이름, 칩, 키/노브 수 전부 | **자동** (진행 순서 1번에서 만든 GUI `Board`) |
| ② 업데이트 모드 | 부트로더가 알려 주는 칩 종류와 칩 고유 ID뿐 | 직전에 연결되어 있던 키보드의 칩 고유 ID(HELLO 32~35)와 같으면 그 보드. 아니면 ③처럼 고르기 |
| ③ 처음 설치 (공장 펌웨어) | 칩 계열 정도 | **사용자가 보드 목록에서 고름**. 감지된 칩 계열에 맞는 보드만 보여 줌 |

③ 처음 설치 흐름:

1. [펌웨어 업데이트] 창을 열고 키보드를 업데이트 모드로 꽂습니다. 공장 펌웨어에는 BOOT 명령이 없으니, 보드 목록의 "사용자 안내"대로 들어갑니다.
2. 칩 목록에 칩이 나타나면, 그 칩 계열의 보드만 골라서 보여 줍니다. 예: CH552 → `MK6K1N`, 8키 보드… / CH57x → 9키 보드….
3. 사용자가 보드를 고르면 그 보드의 펌웨어 파일을 기본으로 채우고, 키 배치 미리 보기를 보여 줍니다(키 수를 눈으로 맞춰 보도록).
4. [장입] 후 키보드가 다시 시작하면 ①로 넘어가 HELLO로 확인합니다. HELLO의 보드 이름이 고른 보드와 다르면 알려 줍니다.

시중의 CH57x 계열 매크로 키보드는 키 수가 달라도 USB ID(`1189:8890`)가 모두 같다고 알려져 있어서, 공장 펌웨어 상태로는 몇 키인지 알 수 없습니다. 그래서 ③은 자동으로 정하지 않고 사용자에게 묻습니다.

### 5-3. 보드별 부트로더 진입 핀

CH55x 부트로더는 업로드할 때 함께 쓰는 **진입 설정**(vnproch55x `-c`)에 따라 "어느 핀을 누른 채 꽂으면 업데이트 모드로 들어갈지"가 정해집니다.

- 진입 설정은 보드 목록의 `boot_config`에서 가져옵니다(MK6K1N: `BOOT_P15`, P1.5 = 키 D). 업데이트 창은 **장입할 보드**를 목록에서 고르게 하고(처음에는 HELLO의 보드), 키보드를 식별할 수 없으면(공장 펌웨어, 보드 정보 없음, 목록에 없는 보드) 고른 보드가 맞는지 확인을 받은 뒤 장입합니다(GUI 1.6.0).
- 다른 기판에서 P1.5가 키가 아니면, 이 값으로 올린 뒤에는 다음 업데이트 때 업데이트 모드로 들어가기 어려워집니다([TROUBLESHOOTING.md 2-3](TROUBLESHOOTING.md#2-3-다운로드-실패-후-장치가-전혀-인식되지-않음-복구)). 그래서 **진입 설정은 보드 목록에서 가져옵니다.**
- 고를 수 있는 진입 설정은 두 가지입니다.
  - **P1.5 풀다운**(`-c 1`): P1.5에 연결된 키를 누른 채 꽂으면 들어갑니다. 그 보드에서 P1.5가 어느 키인지 보드 목록에 적고, 안내 문구도 그 키 이름으로 만듭니다(예: "키 D를 누른 채").
  - **P3.6(USB D+) 풀업**(`-c 3`, CH55xDuino 기본값): 키가 아니라 D+ 선을 3.3V에 잇는 방식이라 사용자가 하기 어렵습니다. P1.5에 키가 없는 보드에서만, 그 보드의 진입 방법(버튼, 패드 등)을 확인한 뒤 씁니다.
- 보드를 모를 때(목록에 없음)는 장입을 막거나, 진입 설정을 바꾸지 않는 방법이 있는지 확인한 뒤 그 방법을 씁니다(아래 "확인할 것").
- 펌웨어 쪽 "노브를 누른 채 꽂기"와 BOOT 명령은 펌웨어가 직접 부트로더로 넘어가므로 진입 핀과 관계없이 됩니다. 다만 펌웨어가 망가졌을 때의 복구 수단은 진입 핀뿐이라 이 값이 중요합니다.
- CH57x의 부트로더 진입 방법은 칩과 기판에 따라 다르므로, 9키 보드가 오면 확인해서 목록에 적습니다.

### 확인할 것

- 8키 보드의 칩(9키 보드는 CH57x 계열로 확인됨)과 두 보드의 핀 배치.
- vnproch55x에서 진입 설정을 바꾸지 않고 펌웨어만 쓰는 방법이 있는지(`-c` 생략 시 동작).
- CH57x 부트로더의 칩 ID 번호와, 칩 고유 ID를 읽을 수 있는지.

## 6. 펌웨어 쪽

- `src/config.h`의 고정값을 **보드 파일**로 옮깁니다: `src/boards/mk6k1n.h`(지금 키보드)에 칩, 키/노브 수, 행 수, 보드 이름, 핀 배치. 빌드할 때 `-DBOARD_MK6K1N`처럼 하나를 고릅니다(`tools/build_fw.ps1 -Board mk6k1n`).
- `SLOT_COUNT`는 `NUM_KEYS + 3 * NUM_KNOBS`로 계산. 잠금 검사(`< SLOT_COUNT`)와 블롭 검사는 이미 이 값을 씁니다.
- 노브가 여러 개인 보드는 이번 범위 밖입니다(엔코더 읽기를 노브마다 반복해야 함). 보드 정보 형식만 미리 열어 둡니다.
- 3단계에서 넣은 핀 배치 검사(`#error`)는 보드 파일별로 둡니다.
- HELLO 응답과 식별 문자열 추가로 117바이트 늘었습니다(8,151 → 8,268바이트, 1.3.0).
- 키 스캔 표(`BOARD_SWITCH_BITS`, P1에 있는 스위치 수 `BOARD_P1_SWITCHES`)도 보드 파일에 있습니다. 키 i는 슬롯 i를 입력합니다.

## 8. CH57x 이식 방침 (9키)

> 2026-10-26 정함. 칩의 정확한 모델(CH570/571/573 등)은 보드가 오면 확인합니다.

- **설정 저장 위치**: CH55x와 같게 **DataFlash 맨 앞에 같은 블롭**(`MK` 헤더, CRC, 슬롯 길이 + 문자열)을 둡니다. 키별 문자열은 **코드 플래시에 쓰지 않습니다**. 용량은 HELLO 바이트 7~8로 알리므로 GUI는 그대로 동작합니다.
- **개발 도구**: WCH 공식 **EVT SDK**(CH573/CH583 예제, USB 장치 예제 포함)의 헤더·드라이버 + **RISC-V GCC**(`riscv-none-elf-gcc`) + Makefile. 지금의 arduino-cli처럼 명령줄로 빌드되게 `tools/build_fw.ps1 -Board`에 연결합니다. 디버깅이 필요하면 MounRiver Studio와 WCH-LinkE를 씁니다. CH57x용 Arduino 코어는 충분히 성숙한 것이 없어서 쓰지 않습니다.
- **소스 구조**: 하드웨어에 매이지 않는 부분(`macro.c`, `lock.c`, `protocol.c`, `storage.c`의 블롭 해석)은 한 벌로 두고, 칩마다 다른 부분은 HAL로 나눕니다.

  | HAL | CH55x | CH57x |
  |---|---|---|
  | 핀 읽기, 키 스캔 | 포트 직접 읽기 (P1/P3) | GPIO 레지스터 (PA/PB) |
  | 시간 (`millis`) | Timer0 | SysTick 또는 TMR |
  | USB 엔드포인트 (키보드, Vendor HID) | CH55xDuino 기반 `src/usb` | EVT의 USB 장치 드라이버 |
  | DataFlash 읽기/지우기/쓰기 | 바이트 단위 쓰기 | 블록 지우기 + 쓰기 |
  | LED | `neopixel_show_P3_4` | 보드에 따라 |
  | 부트로더로 넘어가기 | `lcall 0x3800` | 칩별 방법 확인 필요 |

  8051 전용 메모리 지정자(`__data`, `__idata`, `__xdata`, `__code`)는 매크로로 감싸 GCC에서는 빈 값이 되게 합니다(host_test가 이미 gcc로 공용 코드를 빌드하므로 출발점이 있습니다).
- **GUI 장입**: CH57x의 ROM 부트로더도 같은 WCH ISP 계열(USB `4348:55E0`, Detect 문자열 `MCU ISP & WCH.CN`)이라 **업데이트 창의 칩 목록과 흐름은 그대로 씁니다**. 바뀌는 것은 업로드 도구뿐입니다: vnproch55x는 CH55x 전용이므로 CH57x 보드는 보드 목록에서 **wchisp**(오픈소스, CH55x/CH57x/CH58x 지원)를 고르게 합니다. 칩 표(`chips.py`)에 CH57x 칩 ID와 업로더 종류를 더합니다.
- **확인할 것**: wchisp가 Windows에서 지금의 WCH 드라이버(CH375DLL)로 동작하는지, 아니면 WinUSB 드라이버가 필요한지 / CH57x 부트로더가 돌려주는 칩 ID와 칩 고유 ID / 앱에서 부트로더로 넘어가는 방법과 기판의 부트 핀.

## 정할 것

1. **프로토콜 버전**: A(v2 유지, 바이트 17로 구분, 권장) / B(v3로 올림).
2. **키 이름**: `A, B, C…`(지금과 같음, 권장) / `1, 2, 3…`.
3. **칩 고유 ID를 HELLO에 넣을지**: 넣으면 업데이트 모드 목록에서 "이 키보드"를 알아볼 수 있습니다. 다만 펌웨어가 읽는 ROM의 칩 ID가 부트로더가 보여 주는 ID(`7D-E2-0F-BD`)와 같은 값인지 장치에서 먼저 확인해야 합니다. 다르면 넣지 않습니다. → **확인함 (2026-10-26, 1.3.0)**: ROM `0x3FFC`~`0x3FFF` 4바이트가 부트로더 ID와 같은 순서로 같습니다.
4. **키 배치 표현**: 행 수 하나로 격자를 만드는 방식(권장, 대부분의 매크로패드에 충분) / 키마다 위치를 주는 방식(배치가 불규칙한 키보드용, 바이트가 더 필요).
5. **다른 보드의 JSON 백업 불러오기**: 같은 이름의 슬롯끼리 옮기기(권장) / 거부.
6. **펌웨어 파일 배포** (2026-10-26 정함): GUI exe에 hex를 넣지 않고 **펌웨어는 따로 빌드**합니다(`tools/build_fw.ps1 -Board`). 업데이트 창은 `macro_keyboard-<보드>.hex`를 먼저 고르고, 처음 설치(진행 순서 4)에서도 사용자가 그 보드의 hex를 고릅니다.
