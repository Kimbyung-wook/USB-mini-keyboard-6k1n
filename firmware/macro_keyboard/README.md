# macro_keyboard: 본 펌웨어 v1.2

6키 + 노브 1개 CH552G 미니 키보드용 펌웨어입니다. 키와 노브 동작마다 저장된 문자열(매크로)을 HID 키보드 입력으로 출력하고, [gui](../../gui/) 설정 프로그램과 [PROTOCOL.md](../../docs/PROTOCOL.md) v2 규격으로 통신합니다.

## 기능

| 항목 | 내용 |
|---|---|
| USB 구성 | 인터페이스 0: HID 키보드, 인터페이스 1: 설정용 Vendor HID (64바이트) |
| 슬롯 | 키 A~F, 노브 시계 방향/반시계 방향/누르기 (9개) |
| 저장 | DataFlash 128바이트. 헤더와 슬롯 길이 정보 26바이트를 빼면 **9개 슬롯 합계 102자** (패턴 암호를 쓰면 `2 + 단계 수`바이트만큼 줄어듦) |
| 매크로 | `{ENTER}` `{TAB}` `{UP}` `{F5}` 등 키 이름, `{CTRL+C}` 같은 조합키, `{DELAY:n}`, `{{` `}}` |
| Caps Lock | 켜져 있어도 영문 대소문자가 쓴 그대로 입력되도록 보정 |
| 연속 입력 | 출력 중에 누른 키는 최대 8개까지 순서대로 대기 |
| 잠금 (v1.1, v1.2에서 변경) | 패턴 암호를 저장하면 꽂을 때마다 잠긴 상태로 시작하고 키에 반응하지 않음. **노브를 2초 누른 뒤** 패턴(4~8단계)을 입력하면 풀림. 풀린 상태에서 같은 방법으로 다시 잠글 수 있음. v1.4부터 GUI에서 정한 시간(분) 동안 입력이 없으면 자동으로 잠김(0분 = 안 함). 상태도는 [README의 잠금 상태도](../../README.md#잠금-상태도) |

### LED (WS2812 1개)

| 색 | 의미 |
|---|---|
| 꺼짐 + 3초마다 빨강이 짧게(0.1초) 깜빡 | 잠김: 키를 눌러도 반응 없음. 노브를 2초 눌러 패턴 입력을 시작 |
| 빨강 (계속 켜짐) | 패턴 입력 중 (풀기 또는 다시 잠그기) |
| 빨강 깜빡임 (약 0.5초 간격) | 풀기를 5번 틀려서 입력을 막음. 다시 꽂아야 함 |
| 파랑 | 풀림 (패턴 암호가 없을 때도) |
| 초록 | 키를 누름 (최소 0.2초, 문자열을 출력하는 동안 계속) |
| 흰색 (0.3초) | 설정 저장 완료 |
| 보라 | 부트로더로 들어가는 중 (v1.0은 빨강) |

### 부트로더 진입 (펌웨어 업데이트)

- **키 D를 누른 채 USB 연결**: ROM 부트로더(P1.5)
- **노브를 누른 채 USB 연결**: 펌웨어가 부트로더로 점프 (키 D 방법이 안 될 때의 예비 방법)
- GUI의 BOOT 명령도 지원합니다(아직 GUI 화면에는 버튼이 없음). 잠긴 동안에는 거부합니다.

### 잠금

1. GUI의 **패턴 암호** 칸에서 키/노브 버튼을 순서대로 눌러 패턴을 만들고(4~8단계) **[장치에 저장]**합니다. 저장한 직후에는 풀린 상태가 유지되고, **다음에 꽂을 때부터** 잠깁니다.
2. 키보드를 꽂으면 **잠김** 상태입니다. LED는 꺼져 있고 3초마다 빨강이 짧게 깜빡입니다. 이때 키와 노브는 아무 반응도 하지 않습니다(틀린 횟수에도 들어가지 않음).
3. **노브를 2초 누르고 있으면** LED가 **빨강으로 계속 켜집니다**. 노브를 놓고 패턴을 순서대로 입력합니다(노브 누르기 ●도 패턴에 쓸 수 있음).
4. 맞으면 LED가 **파랑**이 되고 평소처럼 동작합니다. 패턴 입력은 타이핑되지 않습니다. 이후 키를 누를 때마다 초록이 잠깐 켜집니다.
5. 틀리면 잠김(꺼짐 + 가끔 깜빡)으로 돌아갑니다. 다시 노브를 2초 눌러 시작합니다. 빨강이 켜진 채로 10초 동안 아무것도 입력하지 않으면 입력이 취소되고 잠김으로 돌아갑니다(틀린 횟수에 들어가지 않음).
6. **5번 틀리면** 빨강이 계속 깜빡이며 입력을 받지 않습니다. 다시 꽂으면 다시 시도할 수 있습니다.
7. **다시 잠그기**: 풀린 상태에서 노브를 2초 누르면 빨강이 켜지고, 같은 패턴을 입력하면 잠김이 됩니다. 이때도 패턴 입력은 타이핑되지 않습니다. 틀리면 풀린 상태(파랑)로 돌아가고, **5번 틀리면 그냥 잠깁니다**(이때는 차단이 아니라 잠김이라 노브 2초 + 맞는 패턴으로 바로 풀 수 있음). 10초 동안 입력이 없으면 잠그지 않고 파랑으로 돌아갑니다.

패턴 암호가 저장되어 있으면 노브 누르기의 문자열은 **누를 때가 아니라 뗄 때** 입력됩니다(2초 넘게 누르면 패턴 입력이 시작되고 문자열은 입력되지 않음). 패턴 암호가 없으면 예전처럼 누를 때 입력됩니다.

꽂는 순간 노브를 누르고 있으면 부트로더로 들어가니, 2초 누르기는 **꽂은 뒤에** 하세요.

잠긴 동안에는 GUI에서 읽기와 테스트 입력이 안 됩니다. 패턴을 잊었으면 GUI에서 새 설정을 **[장치에 저장]**하면 됩니다. 이때 기존 문자열과 패턴은 모두 지워집니다.

이 잠금은 주변 사람이 키를 눌러 보는 것을 막는 정도입니다. 펌웨어를 새로 구워 DataFlash를 읽는 것까지는 막지 못하니 비밀번호 같은 민감한 문자열은 저장하지 마세요.

## 빌드

Arduino IDE + CH55xDuino 0.0.26 (Windows는 [TROUBLESHOOTING 1-1](../../docs/TROUBLESHOOTING.md)의 `sdcc.sh` 패치 필요).

| Tools 메뉴 | 값 |
|---|---|
| Board | CH552 Board |
| Clock Source | 24 MHz (internal), 5V |
| USB Settings | **USER CODE w/ 266B USB ram** ⚠️ test_pinmap(148B)과 다릅니다 |
| Bootloader pin | **P1.5 pull-down** |

**빌드 스크립트 (권장)**: 저장소 폴더에서 실행하면 위 보드 설정으로 빌드하고 **빌드한 시각**을 펌웨어에 넣습니다. 결과는 `firmware\macro_keyboard\build\macro_keyboard.ino.hex`입니다.

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_fw.ps1
```

**Arduino IDE**: **Sketch → Export Compiled Binary**를 누르면 `build\CH55xDuino.mcs51.ch552\macro_keyboard.ino.hex`가 생깁니다. 이렇게 빌드하면 빌드 날짜가 들어가지 않습니다(GUI에 `빌드 날짜 없음`).

### 버전과 빌드 날짜

- **버전**은 `src/config.h`의 `FW_MAJOR`, `FW_MINOR`, `FW_PATCH`를 직접 고칩니다(지금 `1.4.0`). USB 장치 정보(bcdDevice)에도 같은 값이 들어갑니다.
- **빌드 날짜**는 `tools/build_fw.ps1`이 빌드 순간의 시각을 컴파일 옵션(`-DFW_BUILD_YEAR=2026` 등)으로 넘깁니다. 컴파일러의 `__DATE__`를 쓰지 않는 이유: Arduino는 바뀌지 않은 파일을 다시 컴파일하지 않아서 예전 날짜가 남습니다.
- GUI 연결 막대에 `펌웨어 v1.1.0 (빌드 2026-10-26 11:40)`처럼 표시됩니다. 펌웨어 1.0은 `펌웨어 v1.0`으로만 보입니다.

확인 결과(2026-10-27, v1.4.0): 프로그램 8446바이트(58%), 전역 변수 359바이트(47%). v1.3.x(8268바이트)에 자동 잠금이 더해졌습니다(+178바이트). v1.2.1(8151바이트)에서 v1.3.0으로는 HELLO 보드 정보와 펌웨어 식별 문자열이 더해졌습니다(+117바이트). v1.2.0(11587바이트, 80%)에서 v1.2.1로는 기능은 그대로 두고 크기만 줄였습니다([docs/FIRMWARE_SIZE.md](../../docs/FIRMWARE_SIZE.md)).

### 보드 파일

칩, 키/노브 수, 키 배치 행 수, 보드 이름, 핀 배치는 **보드 파일** `src/boards/<보드>.h`에 있습니다([docs/BOARD_INFO.md](../../docs/BOARD_INFO.md) 6). 지금은 `mk6k1n.h`(이 키보드) 하나입니다.

- `tools/build_fw.ps1 -Board mk6k1n`이 `-DBOARD_MK6K1N`으로 보드를 고르고, 결과를 `build/macro_keyboard-MK6K1N.hex`로도 복사합니다(GUI의 펌웨어 업데이트 창이 먼저 고르는 파일). `-Board`를 빼면 `mk6k1n`입니다. Arduino IDE에서 빌드해도 `mk6k1n`이 됩니다.
- 펌웨어는 HELLO 바이트 17~35로 보드 정보를 보내고([docs/PROTOCOL.md](../../docs/PROTOCOL.md)), hex 안에 식별 문자열 `MKFW1:<보드>:<칩>:<버전>`(예: `MKFW1:MK6K1N:CH552:1.3.0`)을 넣습니다. GUI는 올리기 전에 이 문자열로 보드와 칩을 확인합니다.
- 보드 이름은 GUI의 보드 목록 `gui/boards.py`와 같아야 합니다.

## 업로드

이 펌웨어(v1.0 이상)가 이미 올라가 있으면 **GUI의 [펌웨어 업데이트]**로 올리는 것이 가장 쉽습니다. 잠금이 풀린 키보드는 GUI가 BOOT 명령으로 업데이트 모드에 넣어 주므로 키 D를 누를 필요가 없습니다([사용 설명서 8장](../../docs/MANUAL.md#8-펌웨어-업데이트)).

스크립트로 올릴 때는 저장소 폴더에서 실행하고, **키 D를 누른 채** 키보드를 연결합니다. `build_fw.ps1`로 빌드했으면:

```powershell
powershell -ExecutionPolicy Bypass -File tools\flash.ps1 -Hex firmware\macro_keyboard\build\macro_keyboard.ino.hex
```

Arduino IDE로 빌드했으면 `-Hex firmware\macro_keyboard\build\CH55xDuino.mcs51.ch552\macro_keyboard.ino.hex`입니다.

업로드 후 LED가 **파랑**으로 켜지면 펌웨어가 실행 중인 것입니다. 처음에는 DataFlash에 이전 제조사 설정이 남아 있어도 형식이 맞지 않으므로 **모든 슬롯이 비어 있는 상태**로 시작합니다.

## 동작 테스트

### 1. 연결 확인

1. GUI를 실행합니다: `gui\.venv\Scripts\python -m gui`
2. 상단에 `● 연결됨 · MK6K1N (키 6 + 노브 1) · 펌웨어 v1.4.0 (빌드 …) · 용량 128바이트`가 보이면 설정 통신이 되는 것입니다. 빌드 날짜가 방금 빌드한 시각인지도 확인하세요(새 펌웨어가 올라갔다는 표시).
3. 처음에는 "설정 없음"으로 빈 슬롯 9개가 표시됩니다.

### 2. 테스트 문자열 넣기

아래 표의 문자열을 GUI에서 슬롯마다 입력하고 **[장치에 저장]**을 누릅니다(9개 합계 85자, 전체 111 / 128바이트). LED가 흰색으로 잠깐 빛나면 저장된 것입니다.

| 슬롯 | 테스트 문자열 | 확인하는 것 |
|---|---|---|
| 키 A | `Hello, World!{ENTER}` | 대소문자, 기호, Enter |
| 키 B | `abc{DELAY:1000}def` | 1초 쉬었다가 이어서 입력 |
| 키 C | `{{OK}}` | 중괄호 입력 → `{OK}` |
| 키 D | `{CTRL+A}` | 조합키 (전체 선택) |
| 키 E | `{CTRL+C}` | 조합키 (복사) |
| 키 F | `{CTRL+V}` | 조합키 (붙여넣기) |
| 노브 시계 방향 | `{DOWN}` | 한 칸마다 아래 화살표 |
| 노브 반시계 방향 | `{UP}` | 한 칸마다 위 화살표 |
| 노브 누르기 | `{ENTER}` | Enter |

### 3. 키보드로 확인

1. **메모장**을 열고 **영문 입력 모드**로 둡니다.
2. 키 A → `Hello, World!` 입력 후 줄바꿈
3. 키 B → `abc` 입력, 1초 뒤 `def`
4. 키 C → `{OK}`
5. 키 D(전체 선택) → 키 E(복사) → 메모장 끝을 클릭 → 키 F(붙여넣기)
6. 노브를 돌려 커서가 위/아래로 움직이는지, 노브를 눌러 줄바꿈이 되는지 확인
7. **Caps Lock을 켜고** 키 A를 다시 눌러도 `Hello, World!`가 그대로 나오는지 확인
8. USB를 뺐다가 다시 꽂고, GUI의 **[장치에서 읽기]**로 저장한 문자열이 그대로 남아 있는지 확인

GUI의 **[테스트 입력]**으로 키를 누르지 않고 선택한 슬롯을 입력해 볼 수도 있습니다(3초 카운트다운 뒤 포커스된 창에 입력됨).

### 4. 잠금 확인

1. GUI의 패턴 암호에 `A → B → C → ↻`(키 A, B, C, 노브 시계 방향 한 칸)를 넣고 저장합니다(전체 117 / 128바이트). LED는 파랑 그대로입니다.
2. USB를 뺐다가 다시 꽂으면 LED가 **빨강**이고, GUI 상단에 `🔒 잠김 … 키보드에서 노브를 2초 누른 뒤 패턴 암호를 입력하세요`가 보입니다.
3. 메모장에서 키 A를 눌러도 아무것도 입력되지 않는지 확인합니다.
4. 노브를 누르지 않고 `A, B, C, ↻`를 입력해도 풀리지 않는지 확인합니다.
5. 노브를 2초 눌러 **빨강이 계속 켜지면** `A, B, D, ↻`처럼 틀리게 입력합니다. 잠김(꺼짐 + 가끔 깜빡)으로 돌아오는지 확인합니다.
6. 다시 노브를 2초 누르고 `A, B, C, ↻`를 입력하면 LED가 **파랑**이 되고, 2초 안에 GUI가 `● 연결됨`으로 바뀌며 설정을 읽어 오는지 확인합니다.
7. 노브를 짧게 누르면 노브 누르기 문자열이 (뗄 때) 입력되는지 확인합니다.
8. **다시 잠그기**: 노브를 2초 눌러 빨강이 켜지면 `A, B, C, ↻`를 입력합니다. 잠김(꺼짐 + 가끔 깜빡)이 되고 2초 안에 GUI가 `🔒 잠김`으로 바뀌는지 확인합니다.
   다시 푼 뒤 다시 잠그기를 5번 틀리게 입력하면 5번째에 잠기는지도 확인합니다.
9. 다시 꽂은 뒤 5번 틀리게 입력하면(매번 노브 2초 후) 빨강으로 깜빡이고, 맞는 패턴도 받지 않는지 확인합니다.
10. **자동 잠금** (v1.4): 풀린 상태에서 GUI의 자동 잠금을 `1분`으로 저장합니다(설정이 3바이트 늘어남). 아무것도 누르지 않고 1분을 기다리면 잠김(꺼짐 + 가끔 깜빡)이 되고 2초 안에 GUI가 `🔒 잠김`으로 바뀌는지 확인합니다. 다시 풀고 1분이 되기 전에 키를 하나 누르면 그때부터 1분을 새로 세는지도 확인합니다.
11. 확인이 끝나면 GUI에서 패턴 암호를 **모두 지우기** 하고 저장하면 잠금이 꺼집니다(자동 잠금도 함께 0분).

### 5. 용량 확인

GUI 아래쪽 막대에 `N자 입력 · M자 더 입력 가능 (사용 / 128 바이트)`가 표시됩니다. 128바이트를 넘으면 빨간색으로 바뀌고 저장 버튼이 꺼집니다.

| 증상 | 확인할 것 |
|---|---|
| 업로드 후 키보드로 인식되지 않음 | 장치 관리자에서 "알 수 없는 장치"가 보이면 USB Settings가 **266B**였는지 확인하고 다시 빌드 |
| GUI가 "연결 안 됨" | 장치 관리자의 HID 장치에 `Mini Macro Kbd`가 두 개(키보드, 공급업체 정의 장치) 있는지 확인. 다른 GUI 창이 장치를 잡고 있지 않은지 확인 |
| 영문 대신 한글이 입력됨 | 한/영 키로 영문 모드로 전환 ([TROUBLESHOOTING 3-1](../../docs/TROUBLESHOOTING.md)) |
| 다시 업로드해야 함 | 키 D 또는 노브를 누른 채 연결 |
| 패턴 암호를 잊음 | 잠긴 채로 GUI에서 새 설정을 **[장치에 저장]** (기존 문자열과 패턴은 지워지고 되찾을 수 없음). 펌웨어를 다시 올려도 DataFlash의 설정은 지워지지 않으므로 다시 올리는 것으로는 풀리지 않음 |

더 자세한 내용은 [docs/TROUBLESHOOTING.md](../../docs/TROUBLESHOOTING.md)를 보세요.

## 코드 구성

| 파일 | 내용 |
|---|---|
| `macro_keyboard.ino` | 키/노브 입력, LED, 부트로더 점프, 메인 루프 |
| `src/config.h` | 버전, 보드 파일 고르기, 슬롯 번호, 용량, 잠금 설정값 |
| `src/boards/mk6k1n.h` | 이 키보드의 보드 정보(칩, 키/노브 수, 이름)와 핀 배치 |
| `src/lock.c/.h` | 잠금 상태, 패턴 입력 판정, 틀린 횟수, 자동 잠금 시간 |
| `src/protocol.c/.h` | Vendor HID 명령 처리 (HELLO/READ/WRITE/COMMIT/TEST/BOOT), HELLO 보드 정보, 펌웨어 식별 문자열 |
| `src/storage.c/.h` | DataFlash 블롭 저장, CRC 검사, 슬롯 찾기 (문자열, 패턴 암호, 설정 슬롯) |
| `src/macro.c/.h` | 매크로 해석과 비동기 출력 (키 누름/뗌, DELAY) |
| `src/usb/` | USB 디스크립터, 요청 처리, 엔드포인트 (CH55xDuino qmkCompatibleKeyboard 예제 기반, LGPL-2.1) |

`firmware/host_test/run.py`로 `storage.c`, `macro.c`, `lock.c`를 PC(gcc)에서 검사할 수 있습니다. GUI의 인코더로 만든 블롭을 저장하고, 각 슬롯이 보내는 HID 키 코드와 패턴 암호 판정을 확인합니다.

```powershell
gui\.venv\Scripts\python firmware\host_test\run.py
```
