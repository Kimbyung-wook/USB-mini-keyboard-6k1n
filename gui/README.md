# 매크로 키보드 설정 프로그램 (GUI)

CH552G 6키 + 노브 1개 USB 매크로 키보드에 저장된 문자열(매크로)을 보고 편집하는 Windows용 PC 프로그램입니다.
![설정 프로그램 화면](../docs/images/gui_main.png)

Python + PySide6로 만들었고, 통신 규격은 [`docs/PROTOCOL.md`](../docs/PROTOCOL.md)(설정 통신 프로토콜 v2)를 따릅니다. 펌웨어 1.0(프로토콜 v1)도 연결되며, 이때는 잠금 기능만 쓸 수 없습니다.

## 설치

**Python 3.12.10** 기준입니다(저장소 루트의 `.python-version`). 저장소 루트에서:

```powershell
py -3.12 -m venv gui\.venv
gui\.venv\Scripts\python -m pip install -r gui\requirements.txt
```

`gui/requirements.txt`에는 실행, 테스트, exe 빌드에 쓰는 패키지가 모두 쓰던 버전 그대로 고정되어 있습니다. 이것 한 번으로 아래의 실행, 테스트, exe 빌드를 모두 할 수 있습니다.

| 패키지 | 용도 |
|---|---|
| `PySide6` 6.12.0 | UI |
| `hidapi` 0.15.0 | USB HID 통신 (모듈 이름 `hid`) |
| `pytest` 9.1.1 | 테스트 |
| `pyinstaller` 6.22.3 | exe 빌드 |

나머지 줄은 위 패키지가 함께 설치하는 것들입니다. 새 PC에서도 같은 버전이 깔리도록 고정했습니다.

pip로 설치하지 않는 도구:

| 도구 | 필요한 작업 | 쓰던 버전 |
|---|---|---|
| Arduino CLI(또는 Arduino IDE) + CH55xDuino | 펌웨어 빌드(`tools\build_fw.ps1`, [펌웨어 README](../firmware/macro_keyboard/README.md)) | Arduino CLI 1.5.1, CH55xDuino 0.0.26 |
| gcc (PATH에 있어야 함) | 펌웨어 PC 검사(`firmware\host_test\run.py`) | MinGW GCC 6.3.0 |

## 실행

저장소 루트에서 실행합니다.

```powershell
# 실제 장치 사용
gui\.venv\Scripts\python -m gui
# 또는
gui\.venv\Scripts\python gui\main.py

# 모의 장치 사용 (장치 없이 동작 확인)
gui\.venv\Scripts\python -m gui --mock
```

`--mock`을 주면 프로그램 안에서 펌웨어를 흉내 내는 모의 장치(`transport.MockDevice`)에 연결합니다.
예제 설정이 미리 들어 있고, 저장한 내용은 프로그램을 끄면 사라집니다.

다른 배치의 키보드 화면은 `--mock-board 키x노브[x행]`으로 볼 수 있습니다(빈 설정으로 시작).

```bash
gui\.venv\Scripts\python -m gui --mock-board 12x2
```

### 키보드 배치 (보드 정보)

화면의 키 그림, 패턴 암호 버튼, 슬롯 수는 연결한 키보드가 HELLO로 알려 주는 **보드 정보**(키 수, 노브 수, 키 행 수, 보드 이름)로 만듭니다([docs/BOARD_INFO.md](../docs/BOARD_INFO.md)). 보드 정보를 보내지 않는 펌웨어(1.0~1.2.x)는 지금 키보드(키 6 + 노브 1, 2행)로 봅니다. 배치가 다른 키보드를 연결하면 화면을 그 키보드에 맞게 다시 만들고, 저장하지 않은 편집이 있으면 먼저 묻습니다.

## 테스트

```powershell
cd gui
.venv\Scripts\python -m pytest
```

UI 테스트는 화면 없이(`QT_QPA_PLATFORM=offscreen`) 실행됩니다.

펌웨어의 저장·문자열 입력·잠금 코드는 PC에서 gcc로 검사합니다(저장소 루트에서, gcc 필요):

```powershell
gui\.venv\Scripts\python firmware\host_test\run.py
```

## 실행 파일(exe) 빌드

저장소 폴더에서 실행합니다. PyInstaller는 `gui\requirements.txt`로 이미 설치되어 있습니다.

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_gui.ps1
```

- 결과: `dist\MacroKeyboardConfig.exe` (Python 없는 PC에서도 실행 가능)
- `-OneDir`을 붙이면 파일 하나 대신 폴더(`dist\MacroKeyboardConfig\`)로 만들어서 더 빨리 실행됩니다.
- `dist\`, `build\`, `*.spec`은 빌드 중간/결과 파일이라 git에서 제외됩니다.

### 버전과 빌드 일자

- 창 제목에 `v1.4.0`이, 상태 표시줄 오른쪽에 `GUI v1.4.0 · 빌드 2026-10-26 09:06`처럼 표시됩니다.
- **버전**은 `gui/version.py`의 `VERSION`을 직접 고칩니다.
- **빌드 일자**는 `tools/build_gui.ps1`이 빌드하는 순간의 시각을 `gui/_build_info.py`에 써서 exe에 넣고, 빌드가 끝나면 이 파일을 지웁니다. 그래서 소스에서 바로 실행하면 `개발 실행 (빌드 전)`으로 표시됩니다.
- PyInstaller를 직접 실행하면 빌드 일자가 들어가지 않으니 꼭 `build_gui.ps1`로 빌드하세요.

## 기능

- **장치가 없으면 아무것도 보여주지 않습니다** (보안): 키/노브 문자열과 패턴 암호는 키보드가 연결되어 있을 때 장치에서 읽어 온 것만 보입니다.
  연결이 끊기거나 키보드가 다시 잠기면 화면의 설정을 **지웁니다**(저장하지 않은 편집도 지워짐). 연결 안 됨 상태에서는 장치 그림, 편집기, 패턴 암호, JSON 버튼이 꺼집니다.
- **연결 막대**: 연결 상태(연결 안 됨 / 연결됨 + 펌웨어 버전과 빌드 날짜 + 저장 용량), [연결]/[연결 끊기], [새로고침].
  실제 장치 모드에서는 2초마다 장치를 확인해서 꽂으면 자동으로 연결하고, 뽑으면 연결 끊김으로 표시합니다.
- **장치 그림**: 키 A~F(윗줄 A B C, 아랫줄 D E F)와 노브의 세 동작(시계 방향 / 반시계 방향 / 누르기).
  누르면 해당 슬롯을 편집합니다. 버튼에 내용 미리보기가 나오고, 저장하지 않은 슬롯은 `*`, 문법 오류가 있는 슬롯은 빨간색으로 표시됩니다.
- **패턴 암호**: 키/노브 버튼(A~F, ↻, ↺, ●)을 눌러 4~8단계 패턴을 만듭니다. [⌫ 한 칸 지우기], [모두 지우기]. 비워 두면 잠금을 쓰지 않습니다.
- **자동 잠금**: 패턴 암호 아래에서 분(0~255)을 정합니다. 풀린 뒤 그 시간 동안 키/노브 입력과 GUI 작업(읽기·저장·테스트 입력)이 없으면 키보드가 잠깁니다. 0분이면 안 함. 패턴 암호가 있을 때만 쓸 수 있고, 펌웨어 1.4.0 이상이 필요합니다(HELLO 기능 비트 bit3). 설정 슬롯 3바이트를 씁니다.
  패턴은 `2 + 단계 수`바이트의 저장 용량을 씁니다. 4단계 미만이면 빨간색으로 표시되고 저장할 수 없습니다. 펌웨어 1.0에 연결하면 이 칸이 꺼집니다.
- **연결 막대**는 세 줄입니다: 상태와 할 일(`🔒 잠김 - …`, `● 연결됨 - 잠금 풀림`), 보드와 용량(`MK6K1N (키 6 + 노브 1) / 용량 128바이트`), 펌웨어 버전과 빌드 날짜. 연결 방식(HID 경로 등)은 마우스를 올리면 보입니다.
- **잠긴 장치**: 연결 막대에 `🔒 잠김 - 키보드에서 노브를 2초 누른 뒤 패턴 암호를 입력하세요`가 표시되고 [장치에서 읽기]와 [테스트 입력]이 꺼집니다.
  키보드에서 패턴을 입력하면 2초 안에(실제 장치 모드) 또는 [새로고침]을 누르면 풀린 것을 알아채고 설정을 읽어 옵니다.
  연결된 채로 키보드에서 다시 잠그면(노브 2초 + 패턴) 역시 2초 안에 잠김으로 바뀌고, 화면에 읽어 왔던 설정은 지워집니다.
  잠긴 채로 [장치에 저장]하면 경고 후 기존 문자열과 패턴을 모두 지우고 화면의 내용으로 바꿉니다(패턴을 잊었을 때).
- **편집기**: 여러 줄 입력, 입력하는 즉시 문법 검사(오류 위치 빨간 밑줄 + 행/열과 설명), 자주 쓰는 표기 삽입 버튼
  (`{ENTER}`, `{TAB}`, `{DELAY:100}`, 조합키 메뉴, 특수 키 메뉴), 짧은 문법 도움말.
- **저장 용량 표시**: `N자 입력 · M자 더 입력 가능 (사용 / 용량 바이트)`. 9개 슬롯 전체 블롭 크기(헤더 8바이트 + 슬롯마다 2바이트 + 문자열 + 패턴 암호) 기준이며, `{ENTER}` 같은 매크로 표기도 쓴 글자 수만큼 차지합니다. 펌웨어 v1.0의 용량은 128바이트(문자열 합계 최대 102자)이고, 장치 미연결 상태와 `--mock`도 128바이트 기준입니다. 넘치면 빨간색으로 바뀌고 저장할 수 없습니다.
- **[장치에서 읽기]**: 장치의 설정을 읽어옵니다. 저장하지 않은 편집이 있으면 먼저 확인합니다.
  장치에 유효한 설정이 없으면(새 장치, 손상) 빈 슬롯 9개로 시작합니다.
- **[장치에 저장]**: 모든 슬롯의 문법과 용량, 패턴 암호를 검사하고, 확인을 받은 뒤 WRITE(56바이트씩) → COMMIT 순서로 저장합니다.
- **[테스트 입력]**: 선택한 슬롯의 문자열을 장치가 실제로 타이핑하게 합니다(TEST 명령).
  확인 후 3초 카운트다운이 있으니 그동안 입력받을 창(예: 메모장)을 클릭하세요.
  장치는 **저장된** 내용을 입력하므로, 편집 중인 내용을 시험하려면 먼저 저장하세요.
- **[JSON 내보내기] / [JSON 불러오기]**: 설정 백업. 장치가 연결되어 있을 때만 쓸 수 있습니다. 불러온 내용은 [장치에 저장]을 눌러야 장치에 반영됩니다.
- 저장하지 않은 편집이 있으면 창 제목에 `*`가 붙고, 종료할 때 확인합니다.
- **[펌웨어 업데이트]**: 업데이트 모드인 칩의 파트 번호와 시리얼 번호(칩 ID)를 목록으로 보여 주고, `.hex`를 고른 뒤 [장입]을 누르면 올립니다(`bootloader.py`, `flasher.py`, `flash_dialog.py`).
  - 칩, 업로더 옵션, 업데이트 모드 들어가는 방법은 **마지막으로 연결된 키보드의 보드**(HELLO 보드 정보, 없으면 기본 보드 MK6K1N)로 **보드 목록**(`boards.py`)과 **칩 표**(`chips.py`)에서 찾습니다([docs/BOARD_INFO.md](../docs/BOARD_INFO.md) 4, 5). 목록에 없는 보드면 부트로더 진입 설정을 모르므로 장입하지 않습니다.
  - 파일 크기를 칩 용량(CH552 14,336바이트)과 비교하고, 넘으면 올리지 않습니다.
  - 펌웨어 1.3.0부터 hex 안에 있는 **식별 문자열**(`MKFW1:MK6K1N:CH552:1.3.0`)을 읽어 어느 보드·칩·버전용인지 보여 줍니다. 칩이 다르면 올리지 않고, 보드가 다르거나 식별 문자열이 없으면(1.2.x 이하, 다른 펌웨어) 한 번 더 묻습니다.
  - 처음 고르는 파일은 `firmware/macro_keyboard/build/macro_keyboard-<보드>.hex`(`tools/build_fw.ps1`이 만듦), 없으면 `macro_keyboard.ino.hex`입니다.
  - 업데이트 모드 칩의 칩 고유 ID가 연결되어 있던 키보드의 것(HELLO 32~35)과 같으면 "방금 연결된 키보드"로 표시합니다.
  - 키보드가 연결되어 있고 잠금이 풀려 있으면 BOOT 명령으로 업데이트 모드에 넣습니다(키 D 필요 없음). 잠겨 있거나 연결되어 있지 않으면 보드 목록의 안내대로 "키 D를 누른 채 다시 꽂으세요"라고 알려 주고 60초 동안 기다립니다.
  - CH55xDuino의 `vnproch55x.exe`를 보드 목록의 옵션(MK6K1N: `-t CH552 -c 1`, 부트로더 진입 핀 P1.5, `tools/flash.ps1`과 같음)으로 실행하고, 출력에서 칩 종류, 부트로더 버전, 쓰기/검증 진행률을 읽어 표시합니다.
  - 업로더는 exe 빌드에 포함되고(`uploader\`), 소스에서 실행할 때는 `MACROKB_UPLOADER` 환경 변수나 설치된 CH55xDuino에서 찾습니다.
  - 끝나면 키보드에 다시 연결합니다. 키별 문자열과 패턴 암호는 그대로 남습니다. `--mock`에서는 쓸 수 없습니다.

## 매크로 문법 요약

| 표기 | 동작 |
|---|---|
| 영문·숫자·기호 (ASCII `0x20`~`0x7E`) | 그대로 입력 |
| 줄바꿈 | `{ENTER}`와 같음 |
| `{{` / `}}` | 문자 `{` / `}` |
| `{ENTER}` `{TAB}` `{ESC}` `{BS}` `{DEL}` `{SPACE}` `{UP}` `{DOWN}` `{LEFT}` `{RIGHT}` `{HOME}` `{END}` `{PGUP}` `{PGDN}` `{INS}` `{F1}`~`{F12}` | 해당 키 |
| `{DELAY:n}` | n밀리초 대기 (1~10000) |
| `{CTRL+C}` `{ALT+F4}` `{WIN+R}` `{CTRL+SHIFT+ESC}` | 조합키 (수식키 CTRL/SHIFT/ALT/WIN, 마지막은 문자 하나 또는 키 이름) |

키 이름은 대소문자를 구분하지 않습니다. `+` 문자 자체와 조합하려면 `{CTRL++}`처럼 씁니다.

## JSON 백업 형식

UTF-8 JSON 파일입니다.

```json
{
  "format": "usb-mini-keyboard-6k1n",
  "version": 1,
  "board": { "name": "MK6K1N", "keys": 6, "knobs": 1 },
  "slots": [
    { "slot": 0, "key": "A",     "label": "키 A",            "macro": "Hello world{ENTER}" },
    { "slot": 1, "key": "B",     "label": "키 B",            "macro": "{CTRL+C}" },
    ...
    { "slot": 6, "key": "CW",    "label": "노브 시계 방향",   "macro": "{RIGHT}" },
    { "slot": 7, "key": "CCW",   "label": "노브 반시계 방향", "macro": "{LEFT}" },
    { "slot": 8, "key": "PRESS", "label": "노브 누르기",      "macro": "{ENTER}" }
  ]
}
```

- `format`, `version`은 반드시 위 값이어야 합니다.
- 불러올 때는 `key`(`A`~, `CW`/`CCW`/`PRESS`, 노브가 여럿이면 `CW2`…)로 슬롯을 찾습니다. 그래서 배치가 다른 키보드의 백업도 **이름이 같은 슬롯끼리** 옮겨지고, 이 키보드에 없는 슬롯은 건너뛴 뒤 어떤 것을 건너뛰었는지 알려 줍니다. `key`가 없는 항목은 `slot` 번호로 찾습니다.
- `board`와 `label`은 사람이 보기 위한 설명이며 불러올 때 쓰지 않습니다.
- 빠진 슬롯은 빈 문자열이 됩니다. 줄바꿈은 `\n`으로 저장됩니다.
- **패턴 암호는 백업에 넣지 않습니다.** 불러와도 화면의 패턴 암호는 그대로입니다.

### 문서의 화면 캡처

`docs/images/`의 화면 그림(MANUAL, 이 문서)은 실제 프로그램 창을 모의 장치에 연결해서 찍은 것입니다. 화면이 바뀌면 다시 찍습니다(화면 없이 동작, 키보드 필요 없음):

```powershell
gui\.venv\Scripts\python tools\capture_screens.py
```

## 파일 구성

| 파일 | 내용 |
|---|---|
| `protocol.py` | 패킷 인코딩/디코딩, 상태 코드, CRC-16/CCITT-FALSE, 설정 블롭 |
| `macro.py` | 매크로 문법 검사기 (오류 위치 포함), 저장 바이트 수 계산 |
| `transport.py` | `HidTransport`(hidapi) / `MockDevice`(펌웨어 시뮬레이터) |
| `device.py` | 장치 클라이언트: HELLO / READ / WRITE + COMMIT / TEST / BOOT, 시간 제한, 오류 처리, 프로토콜 v1/v2 |
| `backup.py` | JSON 백업 읽기/쓰기 |
| `flasher.py` | 펌웨어 업로드: 업로더 찾기, HEX 읽기(크기, 펌웨어 식별 문자열), 업로더 명령, 업로더 출력 해석 |
| `boards.py` | 보드 목록: 보드 이름, 배치, 부트로더 진입 설정, 업데이트 모드 안내, 펌웨어 파일 이름 |
| `chips.py` | 칩 표: 칩 ID별 이름, 플래시 용량, 지원 여부 |
| `bootloader.py` | 업데이트 모드 칩 검색: WCH 드라이버(`CH375DLL64.dll`)로 Detect/ReadConfig만 보내 파트 번호, 칩 ID, 부트로더 버전을 읽음 |
| `flash_dialog.py` | [펌웨어 업데이트] 창 (인식된 칩 목록, [장입] 시 QProcess로 업로더 실행) |
| `widgets.py`, `app.py` | PySide6 UI (장치 그림, 매크로 편집기, 패턴 암호·자동 잠금 편집기) |
| `version.py` | GUI 버전(`VERSION`)과 빌드 일자 표시. 빌드 일자는 빌드 때 생성되는 `_build_info.py`에서 읽음 |
| `tests/` | pytest 테스트 |

## 알려진 제한

- **ASCII만 지원**합니다. 한글 등은 입력할 수 없고, 키 입력은 US 키보드 배열 기준입니다.
- 저장 용량은 128바이트(9개 슬롯 합계 102자, 패턴 암호를 쓰면 그만큼 줄어듦)입니다.
- `--mock` 모의 장치는 키보드가 없어서 잠금을 풀 수 없습니다. 모의 장치에서 패턴을 저장해도 "다음에 꽂을 때"가 없으므로 잠기지 않습니다.
- 펌웨어 업데이트는 **보드 목록(`boards.py`)에 있는 보드**만 됩니다. 지금은 MK6K1N과 MK6K1NL(둘 다 CH552, 부트로더 진입 핀 P1.5)입니다. 처음 설치(공장 펌웨어)할 때 보드를 고르는 화면은 아직 없습니다([docs/BOARD_INFO.md](../docs/BOARD_INFO.md) 진행 순서 4).
- 업로더(`vnproch55x.exe`와 DLL)는 CH55xDuino(LGPL-2.1)에 포함된 것이고, `CH375DLL.dll`은 WCH의 드라이버 DLL입니다. exe를 다른 사람에게 배포할 때는 이 사실과 라이선스를 함께 알리세요.
- 장치 통신은 UI 스레드에서 동기적으로 처리합니다(128바이트, 몇 번 왕복이라 금방 끝남).
